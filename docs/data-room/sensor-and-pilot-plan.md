# แผนเซนเซอร์และ Pilot

ปรับปรุง 15 ตุลาคม 2569 เป็นแผนผลิตภัณฑ์และการทดลอง ยังไม่มีเซนเซอร์เชื่อมจริงหรือโรงงานตอบรับ

## สิ่งที่จะติดตั้ง

| ส่วนประกอบเป้าหมาย | หน้าที่ | สิ่งที่ยังต้องยืนยัน |
|---|---|---|
| เซนเซอร์การสั่น | เก็บข้อมูลสภาพมอเตอร์ ปั๊ม หรือสปินเดิล | ย่านความถี่ อัตราเก็บข้อมูล จุดยึด สเกล และการสอบเทียบ |
| เซนเซอร์อุณหภูมิ | ติดตามอุณหภูมิบริเวณที่เหมาะสมกับเครื่อง | ตำแหน่งวัด ช่วงอุณหภูมิ ความคลาดเคลื่อน และเกณฑ์ตามคู่มือเครื่อง |
| Gateway | รับข้อมูลจากหลายชุดและส่งเข้าระบบ | โปรโตคอล การเข้ากันได้ ระยะรับสัญญาณ เครือข่าย และจำนวนเครื่องที่รองรับ |
| Dashboard / ฐานข้อมูล | แสดงสถานะ แนวโน้ม และประวัติ | ระบบหลังบ้าน สิทธิ์ผู้ใช้ การเก็บข้อมูล และการสำรองข้อมูล |
| LINE Messaging | ส่งข้อความแจ้งเตือนให้ผู้รับที่ตกลง | LINE OA/API ผู้รับที่อนุญาต ค่าใช้จ่าย และการส่งจริง |
| หน้าช่าง | รับทราบ บันทึกสิ่งที่ตรวจพบ และปิดงาน | ระบบหลายผู้ใช้ ผู้รับผิดชอบ และ audit log |

ยังไม่กำหนดยี่ห้อหรือรุ่น ไม่รับรองว่าอุปกรณ์ทั้งหมดซื้อได้ภายในต้นทุนสมมติ 10,000 บาทต่อชุด ต้องทำ BOM และสำรวจหน้างานก่อนเสนอขาย สเปกของ INDUSTRIAI ยังไม่เทียบเท่ารุ่นคู่แข่งที่อ้างราคา

## ขั้นตอนเป้าหมาย

1. เซนเซอร์ส่งค่าผ่าน Gateway พร้อม timestamp และรหัสเครื่อง
2. ระบบตรวจคุณภาพข้อมูลและความผิดปกติตามเกณฑ์ที่ตกลงกับโรงงาน
3. Dashboard และการแจ้งเตือนส่งข้อมูลให้ช่างที่รับผิดชอบโดยตรง พนักงานสามารถแจ้งเหตุเพิ่มเติมได้
4. ช่างกดรับทราบ ตรวจตามขั้นตอนโรงงาน และบันทึกผลที่ใช้ยืนยันหรือปฏิเสธ alert
5. สรุปเหตุผิดปกติ เวลาตอบรับ และ downtime ที่เทียบกับ baseline ได้

ปัจจุบัน Demo จำลองขั้นตอนเหล่านี้ในเบราว์เซอร์ ตัวอย่าง 80°C และ 5 mm/s ไม่ใช่เกณฑ์ความปลอดภัยหรือมาตรฐานใช้จริง ระบบไม่ได้ควบคุมหรือสั่งหยุดเครื่องจักร

ระยะแรกตั้งใจใช้ baseline และเกณฑ์ที่ช่างทบทวนก่อนพัฒนา AI ข้อมูลที่มีอยู่ยังไม่เพียงพอสำหรับฝึกโมเดล ทำนาย Remaining Useful Life หรือรับรองความแม่นยำ

## Pilot กลุ่มแรก

- เป้าหมาย 3 โรงงานชิ้นส่วนโลหะ/ยานยนต์ในชลบุรี–ระยอง โรงงานละ 3 เครื่อง
- ระยะเวลา 8 สัปดาห์ต่อโรงงาน ทั้งหมดเป็นเป้าหมาย ยังไม่มีโรงงานยืนยัน
- สัปดาห์ 1–2: สำรวจจุดติดตั้ง เก็บ baseline กำหนดชั่วโมงเดินเครื่องและการนับ downtime ร่วมกับช่าง
- สัปดาห์ 3–6: ติดตามข้อมูล ตรวจเหตุแจ้งเตือน และเก็บผลยืนยันจากช่าง
- สัปดาห์ 7–8: เปรียบเทียบกับ baseline และทบทวนความเหมาะสมก่อนขยาย

หากจำนวนเหตุผิดปกติน้อยหรือสภาพการผลิตต่างจาก baseline อาจต้องขยายเวลา ห้ามสรุปความแม่นยำหรือผลลด downtime จากจำนวนเหตุไม่เพียงพอ

### เกณฑ์ประเมินที่เสนอ

| ตัวชี้วัดเป้าหมาย | วิธีนับ |
|---|---|
| ข้อมูลครบอย่างน้อย 95% | จุดข้อมูลที่รับและใช้ได้ / จุดที่คาดว่าจะได้รับ ตามช่วงเวลาและชั่วโมงเดินเครื่องที่ตกลง |
| Alert precision อย่างน้อย 80% | เหตุแจ้งเตือนที่ช่างยืนยันว่าผิดปกติจริง / เหตุแจ้งเตือนที่ตรวจสอบครบ พร้อมระบุจำนวนเหตุ |
| ลด downtime อย่างน้อย 25% | เทียบ baseline โดยปรับตามชั่วโมงเดินเครื่องและภาระการผลิต ระบุข้อจำกัดก่อนอ้างผล |

ตัวเลขเหล่านี้เป็นเกณฑ์ที่เสนอ **ยังไม่มีผลทดลอง** Precision ไม่บอกจำนวนเหตุเสียที่ระบบพลาด จึงต้องบันทึกเหตุผิดปกติที่ไม่แจ้งเตือนและประเมิน recall เพิ่มเมื่อมีข้อมูลเพียงพอ เป้าลด 25% ไม่ใช่การรับประกัน

## เป้าปี 2027

| ระยะ | เป้าหมาย |
|---|---|
| ภายใน 31 มีนาคม | เชื่อมเซนเซอร์จริง ยังไม่มีลูกค้าชำระเงินปลาย Q1 |
| ภายใน 30 มิถุนายน | เริ่ม Pilot กลุ่มแรก 3 โรงงาน เป้าลูกค้าชำระเงินสะสมปลาย Q2 รวม 2 โรงงาน |
| ปลาย Q3 | ลูกค้าชำระเงินสะสม 5 โรงงาน |
| ภายใน 31 ธันวาคม | ลูกค้าชำระเงินสะสม 8 โรงงาน รวม 80 เครื่อง สมมติเฉลี่ย 10 เครื่อง/โรงงาน |

Funnel ตลอดปีที่ตั้งสมมติฐาน: ติดต่อ 40 โรงงาน สาธิต 20 ราย ทดลองรวม 10 โรงงาน และได้สัญญา 8 โรงงาน กลุ่ม Pilot แรก 3 โรงงานนับรวมใน 10 ราย ไม่ใช่เพิ่มอีก 3 ราย อัตราเปลี่ยนเป็นลูกค้า 80% จาก Pilot เป็นสมมติฐานที่ยังไม่ทดสอบ

ราคาและเงื่อนไข Pilot ต้องตกลงกับแต่ละโรงงาน เอกสารนี้ไม่อ้างว่ามี Pilot ฟรีหรือได้รับเงินแล้ว ใช้ราคาเสนอจำลองที่แยกอุปกรณ์ ติดตั้ง Gateway และค่าบริการใน [สมมติฐานการเงิน](financial-assumptions.md) เพื่อคุยขอบเขตก่อนทดลอง
